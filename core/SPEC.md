# 行为契约（SPEC）

这份文档定义「什么算未引用」「怎么移动」「日志说什么」——**实现可以换，契约不能漂**。

- C++ 实现：`desktop/src/core.h`（桌面版）
- JS 实现：`shared/md-cleaner-core.js`（三个插件）
- 基准用例：`core/cases/*.json`（由 `core/gen_cases.py` 用原 PyQt5 版跑出来的）
- 对拍脚本：`core/check.py`（C++ 侧）、`shared/test_core.js`（JS 侧）

改任何一条规则，都要同步改两边实现 + 重新生成基准，并让 `core/check.py`、`shared/test_core.js`、
`tools/test_plugins.js` 三条命令全绿。

---

## 1. 目录约定

| 输入 | 推导出的资源夹 |
| --- | --- |
| `D:\notes\周报.md` | `D:\notes\周报.assets\` |
| `D:\notes\周报.markdown` | `D:\notes\周报.assets\`（后缀整段替换，不是拼接） |

- 资源夹不存在 → 报「文件夹不存在」，不动任何文件。
- 资源夹存在但没有图片 → 报「未找到图片文件」。
- 只扫**这一层**，不进子目录（`deleted_images/` 因此天然被排除）。

## 2. 图片白名单

```
.png .jpg .jpeg .bmp .svg .tiff .webp .gif
```

大小写不敏感（`.PNG` 也算）。白名单之外的文件（如 `notes.txt`）一律无视，不统计、不移动。

## 3. 引用提取

设 `md` 正文为输入，输出「被引用的文件名集合」。两条正则都跑，结果并集去重：

```
!\[[^\]]*\]\(([^)]+)\)
\[[^\]]*\]\(([^)]+)\)
```

- 只取 `basename`：`![](../img/a.png)` 与 `![](a.png)` 都记作 `a.png`，不解析上级目录。
- 第二条会顺带匹配 `![](...)`，这是等价实现，不额外处理。
- **兼容模式**（桌面版默认）：只有上面两条。
- **增强模式**（插件默认）：额外识别
  - wiki 嵌入 `![[a.png]]`、`![[a.png|300]]`（去掉 `|` 之后的参数）
  - HTML `<img src="a.png">`（单双引号都认，属性顺序不限）

## 4. 判定与统计

```
未引用 = { 资源夹里的图片 } - { 被引用的文件名 }
已引用 = { 被引用的文件名 } ∩ { 资源夹里的图片 }
```

- 「未引用」按**文件名排序**后展示；「已引用」按 md 中**首次出现顺序**去重展示
  （原版用 `list(set(...))`，受哈希随机化影响每次顺序不同，已修正）。
- **统计数字口径**：`已引用 N 张` 里的 N 是「被引用文件名的去重个数」，
  **不等于**资源夹里真实存在的已引用图片数——引用了一张不存在的图，也照样计入 N。

## 5. 移动规则

- 目标目录：`<资源夹>/deleted_images/`
- **只在真的要移动时才创建**该目录（`--check` 模式全程零副作用）；已存在则复用，**不清理里面的旧内容**。
- 只移动「未引用」里被勾选的项；已勾选但文件已不存在的，记一行日志跳过，不报错中断。
- 目标重名的处理，两端略有差异（都**绝不覆盖**已有文件）：
  - 桌面版用 `MoveFileW`，目标已存在会直接失败，记「错误: 无法移动 {文件名}: 文件已存在」，原文件留在原地；
  - 插件（JS 侧 `moveFiles`）自动加 `(1)`、`(2)` 后缀后照常移动。
- 只接受纯文件名，拒绝 `../`（插件侧有显式校验）。
- **永远不删除**，最坏情况是移动到 `deleted_images`。

## 7. 进度节奏

```
(5, 准备分析...) → (15, 正在查找引用图片...) → (20, 正在分析图片引用...)
→ (25, 找到 N 张未引用的图片)
→ 预览阶段 25→40（正在准备预览...）→ (40, 预览准备完成)
→ (45, 准备清理...) → 清理阶段 50→95（已清理 i/N）
→ (98, 正在整理结果...) → (100, 清理完成)
```

结束后进度文案统一回到 `就绪`。

## 8. 界面文案与几何

| 元素 | 文案 | 字号 |
| --- | --- | --- |
| 窗口标题 | `Typora清理未引用图片` | — |
| 左侧大标题 | `Typora未引用图片清理工具` | 20pt Bold |
| 主按钮 | `选择Markdown文件并清理` | 14pt |
| 分组框 | `操作日志` / `图片预览` | 12pt Bold |
| 进度标签 | `进度: ` / `就绪` | 12pt |
| 路径标签 | `未选择文件` / `当前文件: {相对路径}` | 12pt |
| 统计标签 | `图片统计: 未引用 0 张，已引用 0 张` | 13pt |
| 预览状态 | `已使用`（#008000）/ `未使用`（#FF0000） | 14px Bold |

- 窗口 `1200×750`，初始位置 `(300, 300)`，分栏比例 **577 : 423**。
- 预览网格列数 = `max(1, (容器宽 - 30) // 420)`，卡片 400×400，间距 30/25，外边距 15。
- 「已引用但文件不存在」的图片仍生成卡片，图区显示 `#C8C8C8` 灰块。
- 路径显示为相对**进程当前工作目录**的路径；跨盘无法相对时回落绝对路径。
- 像素级对齐基准见 `docs/ref_original_*.png` 与 `docs/new_*.png`（差异 0.5%，全在字体抗锯齿边缘）。

## 9. 已知不确定性

| 项 | 说明 | 处理 |
| --- | --- | --- |
| 「已引用」顺序 | 原版受 Python 哈希随机化影响 | 改为按 md 出现顺序，集合内容不变 |
| 未引用缩略图 | 原版先移文件再读图，出现灰块竞态 | 新版先 `FlushPreview()` 再移动 |
| `.webp` 解码 | GDI+ 需系统装过 WebP 扩展 | 解不出走灰块兜底，不崩 |
| 文字抗锯齿 | Qt 与 GDI 渲染相位不同 | 接受像素差，布局零错位为准 |
